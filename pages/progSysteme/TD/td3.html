1. Principe général et architecture du projet

L'objectif de ce TD est de comprendre et d'implémenter cinq algorithmes classiques d'ordonnancement de processus/tâches en langage Go. À chaque unité de temps (appelée pas de temps ou tick), le programme principal interroge la fonction d'ordonnancement choisie pour savoir quelle tâche doit occuper le processeur.

Fichier Rôle dans le module ordo Option -sched
ordo.go Fonction main, lecture JSON, boucle temporelle et serveur web (:8080) -
fcfs.go FCFS - First Come First Served (premier arrivé, premier servi) 0 (défaut)
sjf.go SJF - Shortest Job First (tâche la plus courte d'abord, non préemptif) 1
srt.go SRT - Shortest Remaining Time (temps restant le plus court, préemptif) 2
rr.go RR - Round Robin (tourniquet avec quantum de temps) 3
static.go Priorités statiques - ordonnancement selon la priorité fixe de la tâche 4
tasks.json Jeu de données d'entrée au format JSON (7 tâches avec ID, priorité, durée et arrivée) -json

Questions du sujet sur ordo.go

  • Paramètres acceptés par le programme : le package flag définit deux options en ligne de commande :
    • -json <fichier> : chemin vers le fichier JSON des tâches (valeur par défaut : "tasks.json").
    • -sched <entier> : numéro de l'ordonnanceur à utiliser (0 = FCFS, 1 = SJF, 2 = SRT, 3 = RR, 4 = Priorités statiques ; défaut : 0).
  • Lancer l'ordonnanceur SRT sur tasks2.json : 
    go run . -json tasks2.json -sched 2
  • Visualisation : une fois le planning calculé, displaySchedule démarre un serveur HTTP local accessible sur http://localhost:8080 qui dessine un diagramme de Gantt (histogramme temporel) en vert pour chaque tâche.

2. Le moteur de simulation (ordo.go) et les données (tasks.json)

Chaque tâche est modélisée par la structure task et lue depuis tasks.json :

ID Priority Duration Arrival
010235
1870
25212
34184
4351
5213
61356

La somme des durées vaut $23 + 7 + 21 + 18 + 5 + 1 + 35 = 110$ pas de temps. La boucle principale de ordo.go s'exécute pour $t \in [0, 110]$ :

  1. Elle récupère la tranche tasks[from:to] contenant uniquement les tâches dont Arrival == t.
  2. Elle appelle runningTask := sched(tasks[from:to]).
  3. Si runningTask != nil, elle enregistre schedule[t] = runningTask.ID et décrémente runningTask.Duration-- directement via le pointeur retourné.
Point technique important : comme chaque ordonnanceur renvoie un pointeur *task vers l'élément stocké dans sa file interne (&tasks[0], &chosen...), la décrémentation runningTask.Duration-- effectuée dans ordo.go met directement à jour la durée restante de la tâche dans l'ordonnanceur (sauf copie locale par valeur). 
// Extrait de ordo.go : boucle d'ordonnancement
nextTask := 0
for t := 0; t < totalDuration+1; t++ {
	from := nextTask
	for nextTask < len(tasks) && tasks[nextTask].Arrival == t {
		nextTask++
	}
	to := nextTask

	runningTask := sched(tasks[from:to])
	if runningTask != nil {
		schedule[t] = runningTask.ID
		runningTask.Duration--
	} else {
		schedule[t] = -1
	}
}

3. Les cinq fonctions d'ordonnancement implémentées

Voici les cinq algorithmes codés pour le TD3, avec leur principe de fonctionnement et leur code Go exact.

3.1 First Come First Served - fcfs.go (-sched 0)

  • Principe : politique FIFO et non préemptive. Les nouvelles tâches sont ajoutées à la fin de la tranche globale tasks.
  • Fonctionnement du code : si la tâche en tête (tasks[0]) a une durée $\leq 0$, elle est retirée (tasks = tasks[1:]) et fcfs s'appelle récursivement jusqu'à trouver une tâche active ou vider la file.
package main

var tasks = []task{}

// Ordonnanceur premier arrivé premier servi (first come first served)
func fcfs(newTasks []task) (currentTask *task) {
	tasks = append(tasks, newTasks...)

	if len(tasks) > 0 && tasks[0].Duration <= 0 {
		tasks = tasks[1:]
		return fcfs(tasks)
	}

	if len(tasks) == 0 {
		return nil
	}

	return &tasks[0]
}

3.2 Shortest Job First - sjf.go (-sched 1)

  • Principe : politique non préemptive qui choisit, parmi toutes les tâches déjà arrivées, celle ayant la plus petite durée totale d'exécution (en départageant les égalités par Arrival).
  • Fonctionnement du code : tant que la tâche pointée par chosen a encore Duration > 0, elle conserve le processeur sans être interrompue. Une fois terminée, la liste tasks est filtrée et triée par durée croissante via sort.Slice.
package main

import "sort"

var chosen *task

func sjf(newTasks []task) (chosenTask *task) {
	tasks = append(tasks, newTasks...)

	// Purge les tâches déjà terminées
	filtered := tasks[:0]
	for _, t := range tasks {
		if t.Duration > 0 {
			filtered = append(filtered, t)
		}
	}
	tasks = filtered

	// Si une tâche est déjà en cours et non terminée, on continue (non préemptif)
	if chosen != nil && chosen.Duration > 0 {
		for i := range tasks {
			if tasks[i].ID == chosen.ID {
				chosen = &tasks[i]
				return chosen
			}
		}
	}

	if len(tasks) == 0 {
		chosen = nil
		return nil
	}

	// Sélectionne la tâche restante de plus petite Duration
	sort.Slice(tasks, func(i, j int) bool {
		if tasks[i].Duration == tasks[j].Duration {
			return tasks[i].Arrival < tasks[j].Arrival
		}
		return tasks[i].Duration < tasks[j].Duration
	})

	chosen = &tasks[0]
	return chosen
}

3.3 Shortest Remaining Time - srt.go (-sched 2)

  • Principe : version préemptive de SJF. À chaque tick, on réévalue toutes les tâches actives et on exécute celle dont la durée restante (Duration) est la plus faible.
  • Fonctionnement du code : contrairement à sjf, il n'y a pas de verrouillage sur chosen : si une tâche plus courte arrive à l'instant $t$, le tri sort.Slice la place immédiatement en tasks[0] et interrompt la tâche précédente.
package main

import "sort"


// Ordonnanceur selon la durée de calcul restante (shortest remaining time)
func srt(newTasks []task) (currentTask *task) {
	tasks = append(tasks, newTasks...)

	// Purge les tâches déjà terminées
	filtered := tasks[:0]
	for _, t := range tasks {
		if t.Duration > 0 {
			filtered = append(filtered, t)
		}
	}
	tasks = filtered

	if len(tasks) == 0 {
		chosen = nil
		return nil
	}

	// Sélectionne la tâche restante de plus petite Duration
	sort.Slice(tasks, func(i, j int) bool {
		return tasks[i].Duration < tasks[j].Duration
	})

	return &tasks[0]
}

3.4 Round Robin (Tourniquet) - rr.go (-sched 3)

  • Principe : partage équitable du temps processeur par quantum de temps. Chaque tâche s'exécute au maximum pendant un quantum avant d'être replacée en queue de file.
  • Fonctionnement du code :
    • Maintient une file circulaire file bornée à 5 tâches actives maximum et un compteur ticks.
    • Lorsque ticks >= 5, la tâche en tête est replacée à la fin de file et ticks est remis à 0.
    • On incrémente ticks++ et on retourne l'adresse de la tâche sélectionnée (chosen := file[0]; return &chosen).
package main

var (
	file  = []task{} // liste de max 5 taches
	ticks = 0        // compte les unites de temps
)

func rr(newTasks []task) (currentTask *task) {
	//Ajout les nouvelles tâches (5 max)
	for _, t := range newTasks {
		if t.Duration > 0 && len(file) < 5 {
			file = append(file, t)
		}
	}

	//Retire les taches termines
	actives := file[:0]
	for _, t := range file {
		if t.Duration > 0 {
			actives = append(actives, t)
		}
	}
	file = actives

	if len(file) == 0 {
		ticks = 0
		return nil
	}

	//Apres 5 unites de temps , on pop devant et on remet a la fin
	if ticks >= 5 {
		tete := file[0]
		file = append(file[1:], tete)
		ticks = 0
	}

	ticks++
	chosen := file[0]
	return &chosen
}
Attention en Go sur chosen := file[0]; return &chosen : chosen est une copie locale de file[0]. Lorsque ordo.go fait runningTask.Duration--, il décrémente la copie chosen et non l'élément file[0] dans la slice, ce qui maintient file[0].Duration inchangé dans file.

3.5 Priorités statiques - static.go (-sched 4)

  • Principe : ordonnancement préemptif basé sur le champ Priority de chaque tâche (à priorité égale, la plus anciennement arrivée passe en premier).
  • Fonctionnement du code : filtre les tâches terminées puis trie tasks avec tasks[i].Priority < tasks[j].Priority (ordre croissant de la valeur numérique de Priority, donc la valeur numérique la plus petite passe en tête).
package main

import (
	"sort"
)

// Ordonnanceur à priorités statiques
func static(newTasks []task) (currentTask *task) {
	tasks = append(tasks, newTasks...)

	// Purge les tâches déjà terminées
	filtered := tasks[:0]
	for _, t := range tasks {
		if t.Duration > 0 {
			filtered = append(filtered, t)
		}
	}
	tasks = filtered

	if len(tasks) == 0 {
		chosen = nil
		return nil
	}

	// Sélectionne la tâche restante de plus petite Duration
	sort.Slice(tasks, func(i, j int) bool {
		if tasks[i].Priority == tasks[j].Priority {
			return tasks[i].Arrival < tasks[j].Arrival
		}
		return tasks[i].Priority < tasks[j].Priority
	})

	return &tasks[0]
}

5. Synthèse des techniques d'ordonnancement

Algorithme Type Critère de sélection Avantage / Risque principal
FCFS (-sched 0) Non préemptif Ordre d'arrivée (Arrival) Simple, mais effet de convoi si une tâche longue arrive tôt
SJF (-sched 1) Non préemptif Durée totale (Duration) minimale Minimise le temps d'attente moyen (non préemptif), risque de famine
SRT (-sched 2) Préemptif Durée restante (Duration) minimale Très réactif aux tâches courtes, mais risque de famine pour les longues
Round Robin (-sched 3) Préemptif Tourniquet FIFO par quantum ($q = 5$) Équitable, aucune famine, temps de réponse borné
Priorités statiques (-sched 4) Préemptif Niveau de priorité fixe (Priority) Respecte l'urgence métier, risque de famine pour les basses priorités

Ordonnanceur (Scheduler)

Composant du système d'exploitation qui décide quelle tâche prête obtient le processeur à chaque instant, et pendant combien de temps.

Pas de temps (Tick)

Unité de temps discrète utilisée par la simulation. À chaque tick $t$, une tâche active voit sa durée restante diminuer de $1$.

Diagramme de Gantt

Représentation graphique horizontale du planning : chaque ligne correspond à une tâche et chaque colonne colorée indique qu'elle s'exécute à l'instant $t$.

FIFO (First In, First Out)

File d'attente classique où le premier élément inséré est le premier traité, sans dépassement.

Ordonnancement préemptif

L'ordonnanceur peut interrompre une tâche en cours d'exécution avant sa fin pour attribuer le processeur à une autre tâche jugée plus urgente.

Ordonnancement non préemptif

Une fois qu'une tâche démarre sur le processeur, elle le conserve jusqu'à ce qu'elle ait complètement terminé sa durée d'exécution.

Quantum de temps

Durée maximale consécutive (ici $5$ unités de temps) accordée à une tâche en Round Robin avant qu'elle ne cède sa place à la suivante.

Famine (Starvation)

Situation où une tâche prête attend indéfiniment le processeur parce que d'autres tâches plus courtes ou plus prioritaires arrivent continuellement.
