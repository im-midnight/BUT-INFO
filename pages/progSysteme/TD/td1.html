1. Principe général et questions du TD1

Lorsqu'au moins deux goroutines accèdent simultanément à une même variable partagée et qu'au moins l'un des accès est une écriture sans synchronisation, il y a une race condition (accès concurrent).

  1. Déterminer s'il existe une ou plusieurs race conditions.
  2. Justifier en cas d'absence, ou identifier les variables et lignes en concurrence.
  3. Protéger les accès critiques avec un sync.Mutex.
  4. Vérifier l'absence de conflit avec l'option -race de Go : 
    go run -race ex1-4.go
  5. En bonus sur ex2.go : remplacer les tranches partagées (com1, com2) par des canaux (chan).

2. Analyse des codes ex0.go et ex1-1.go à ex1-5.go

ex0.go — Échange de x et y avec sync.Mutex

Même si un commentaire indique x, y = y, x // race condition, l'échange est entouré de mutex.Lock() et mutex.Unlock() dans la boucle de switchxy(). L'accès concurrent à x et y est donc sérialisé.

package main

import (
	"fmt"
	"sync"
)

var x, y int
var w sync.WaitGroup
var mutex sync.Mutex

func switchxy() {
	for i := 0; i < 1000; i++ {
		mutex.Lock()
		x, y = y, x // race condition
		mutex.Unlock()
	}
	w.Done()
}

func main() {
	x = 5
	y = 7
	w.Add(1000)
	for i := 0; i < 1000; i++ {
		go switchxy()
	}
	w.Wait()
	fmt.Println("x vaut", x, "et y vaut", y)
}

ex1-1.go — Séquentiel et sans mémoire partagée

Pas de mot-clé go et res est une variable locale retournée par valeur : aucune race condition possible.

package main

import "fmt"

// calcule n puissance m
// sequentiel dont pas de race condition
func puissance(n, m int) (res int) {
	res = 1
	for i := 0; i < m; i++ {
		res *= n
	}
	return
}

func main() {

	for i := 0; i < 10; i++ {
		for j := 0; j < 3; j++ {
			fmt.Println(i, "puissance", j, "vaut", puissance(i, j))
		}
	}

}

ex1-2.go — Parallèle mais sans mémoire partagée

Chaque goroutine exécute puissance(i, j) avec sa propre variable locale var res int = 1. Comme il n'y a pas d'état partagé mutable entre goroutines, il n'y a pas de race condition.

package main

import (
	"fmt"
	"sync"
)

var w sync.WaitGroup

// calcule n puissance m
// pas sequentiel
// pas de memoire partage => pas de race contion
func puissance(n, m int) {
	var res int = 1
	for i := 0; i < m; i++ {
		res *= n
	}
	fmt.Println(n, "puissance", m, "vaut", res)
	w.Done()
	return
}

func main() {
	//w.Add(10*3)
	for i := 0; i < 10; i++ {
		for j := 0; j < 3; j++ {
			w.Add(1)
			go puissance(i, j)
		}
	}

	w.Wait()
}

ex1-4.go — Variable globale res protégée par mu.Lock()

Plusieurs goroutines s'exécutent en concurrence et accèdent à la variable globale res, mais mu.Lock() est posé avant res = 1 et mu.Unlock() après fmt.Println : la section critique est protégée.

package main

import (
	"fmt"
	"sync"
)

var res int
var w sync.WaitGroup
var mu sync.Mutex
// calcule n puissance m
//pas sequentiel (mot cle go)
// memoire partage => race condition
func puissance(n, m int) {
	mu.Lock()// Lock avant l'utilsation de la variable global
	res = 1

	for i := 0; i < m; i++ {
		res *= n // race condition
	}
	
	fmt.Println(n, "puissance", m, "vaut", res)// unlock apres la derniere utilisation
	mu.Unlock()
	w.Done()
	return
}

func main() {

	for i := 0; i < 10; i++ {
		for j := 0; j < 3; j++ {
			w.Add(1)
			go puissance(i, j)
		}
	}

	w.Wait()
}

ex1-5.go — Pointeur partagé *res protégé par mu.Lock()

Toutes les goroutines reçoivent l'adresse &res de la variable res de main. L'accès à *res est protégé par mu.Lock() et mu.Unlock().

package main

import (
	"fmt"
	"sync"
)

var w sync.WaitGroup
var mu sync.Mutex
// calcule n puissance m
// pas sequentiel , ya du parallelisme
// memoire partage => race condition
func puissance(n, m int, res *int) {
	mu.Lock()
	*res = 1
	for i := 0; i < m; i++ {
		*res *= n
	}
	fmt.Println(n, "puissance", m, "vaut", *res)
	mu.Unlock()
	w.Done()
	return
}

func main() {
	var res int

	for i := 0; i < 10; i++ {
		for j := 0; j < 3; j++ {
			w.Add(1)
			go puissance(i, j, &res)
		}
	}

	w.Wait()
}

3. ex2.go : producteur, transmetteur, consommateur

3.1 Ébauche fournie

Les tranches globales com1 et com2 sont accédées par plusieurs goroutines sans protection : c'est la race condition que les versions 3.2 (Mutex) et 3.3 (canaux) corrigent.

package main

import (
	"log"
	"sync"
)

var com1, com2 []int
var w sync.WaitGroup

func prod(n int, com chan int) {
	defer w.Done()
	for i := 0; i < n; i++ {
		com1 = append(com1, i)
	}
}

func trans(com1 chan int,com2 chan int) {
	defer w.Done()
	for {
		// if len(com1) > 0 {
		// 	com2 = append(com2, com1[0])
		// 	com1 = com1[1:]
		// }
		temp:=<-com1
		com2<-temp
	}
}

func cons(com chan int) {
	defer w.Done()
	for {
		if len(com2) > 0 {
			log.Print(com2[0])
			com2 = com2[1:]
		}
	}
}

func main() {
	var c chan int = make(chan int,5)
	var c2 chan int = make(chan int,5)
	w.Add(3)
	go prod(1000)
	go trans()
	go cons()
	w.Wait()
}

3.2 Version terminée avec sync.Mutex (question 3 & 4)

Chaque accès à com1 et com2 est protégé par mu1 et mu2, et chaque étape s'arrête proprement une fois les n éléments produits, transférés et consommés :

package main

import (
	"log"
	"sync"
)

var com1, com2 []int
var mu1, mu2 sync.Mutex
var w sync.WaitGroup

func prod(n int) {
	defer w.Done()
	for i := 0; i < n; i++ {
		mu1.Lock()
		com1 = append(com1, i)
		mu1.Unlock()
	}
}

func trans(n int) {
	defer w.Done()
	traites := 0
	for traites < n {
		mu1.Lock()
		if len(com1) > 0 {
			val := com1[0]
			com1 = com1[1:]
			mu1.Unlock()

			mu2.Lock()
			com2 = append(com2, val)
			mu2.Unlock()

			traites++
		} else {
			mu1.Unlock()
		}
	}
}

func cons(n int) {
	defer w.Done()
	consommes := 0
	for consommes < n {
		mu2.Lock()
		if len(com2) > 0 {
			val := com2[0]
			com2 = com2[1:]
			mu2.Unlock()

			log.Print(val)
			consommes++
		} else {
			mu2.Unlock()
		}
	}
}

func main() {
	const n = 1000
	w.Add(3)
	go prod(n)
	go trans(n)
	go cons(n)
	w.Wait()
}

3.3 Version bonus avec canaux (question 5)

En utilisant les canaux c et c2 créés dans main, il n'y a plus de tranches partagées : prod ferme c à la fin, trans lit c avec range et ferme c2 à la fin, et cons lit c2 avec range :

package main

import (
	"log"
	"sync"
)

var w sync.WaitGroup

func prod(n int, com chan int) {
	defer w.Done()
	defer close(com)
	for i := 0; i < n; i++ {
		com <- i
	}
}

func trans(com1 chan int, com2 chan int) {
	defer w.Done()
	defer close(com2)
	for temp := range com1 {
		com2 <- temp
	}
}

func cons(com chan int) {
	defer w.Done()
	for val := range com {
		log.Print(val)
	}
}

func main() {
	c := make(chan int, 5)
	c2 := make(chan int, 5)
	w.Add(3)
	go prod(1000, c)
	go trans(c, c2)
	go cons(c2)
	w.Wait()
}

Race condition (Accès concurrent)

Situation où plusieurs goroutines accèdent en même temps à une ressource partagée et qu'au moins une écriture n'est pas synchronisée, rendant le résultat dépendant de l'entrelacement des exécutions.

Goroutine

Fil d'exécution léger géré par le runtime Go, lancé avec le mot-clé go pour exécuter une fonction de manière concurrente.

Mutex (sync.Mutex)

Verrou d'exclusion mutuelle : une seule goroutine peut détenir le verrou (Lock()) à la fois ; les autres attendent jusqu'à Unlock().

Section critique

Portion de code qui lit ou modifie une variable partagée et qui doit être exécutée de manière atomique vis-à-vis des autres goroutines.

Canal (chan)

Tube typé en Go permettant aux goroutines de communiquer et de synchroniser l'échange de valeurs (ch <- val et <-ch) plutôt que de partager de la mémoire brute.
