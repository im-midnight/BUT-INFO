1. Pourquoi Spring Boot ?

Avec les servlets et JPA bruts, on passe énormément de temps sur la plomberie : installer Tomcat, configurer web.xml et persistence.xml, ouvrir les transactions à la main, parser les paramètres HTTP et écrire les mêmes requêtes CRUD en boucle.

Spring Boot est un framework Java construit au-dessus de Spring qui élimine presque toute cette configuration grâce à trois idées clés :

  • Auto-configuration : Spring Boot détecte les bibliothèques présentes dans ton projet (Gradle ou Maven) et configure tout automatiquement avec des réglages par défaut intelligents.
  • Les Starters : au lieu d'ajouter 15 dépendances à la main, tu ajoutes un seul pack (ex. spring-boot-starter-web pour le web, spring-boot-starter-data-jpa pour la base de données).
  • Serveur embarqué : Tomcat est directement intégré dans ton application. Tu lances une simple méthode main() et ton serveur web démarre sur le port 8080.
@SpringBootApplication // Active la config auto + le scan de tes classes
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

2. Injection de dépendances et architecture en couches

Le cœur de Spring, c'est l'Inversion de Contrôle (IoC) et l'Injection de Dépendances (DI). Au lieu de faire new ProductService() partout dans ton code, tu laisses Spring créer, conserver et relier tes objets — appelés Beans — à ta place.

Une application Spring Boot propre est découpée en 3 couches, chacune repérée par une annotation :

CoucheAnnotationRôle
Web / Présentation@RestController ou @ControllerReçoit les requêtes HTTP, valide les entrées et renvoie JSON ou une vue HTML.
Métier@ServiceContient les règles métier (calculs, vérifications, orchestration).
Données@RepositoryCommunique avec la base de données (géré automatiquement par Spring Data JPA).

Injecter une dépendance proprement (par constructeur)

@Service
public class ProductService {
    private final ProductRepository repository;

    // Spring injecte automatiquement l'instance de ProductRepository
    public ProductService(ProductRepository repository) {
        this.repository = repository;
    }

    public List<Product> listerTous() {
        return repository.findAll();
    }
}

Privilégie toujours l'injection par constructeur avec un attribut final (plutôt que @Autowired sur un champ privé) : tes dépendances sont garanties présentes et faciles à tester en unitaire.

3. Créer une API web avec @RestController

Fini extends HttpServlet, doGet() et PrintWriter ! Avec Spring Web, une simple classe annotée @RestController associe chaque URL et verbe HTTP à une méthode Java, et convertit automatiquement tes objets Java en JSON (et inversement).

@RestController
@RequestMapping("/api/products") // Préfixe commun à toutes les routes
public class ProductController {

    private final ProductService service;

    public ProductController(ProductService service) {
        this.service = service;
    }

    // GET /api/products?minPrice=10
    @GetMapping
    public List<Product> getAll(@RequestParam(defaultValue = "0") double minPrice) {
        return service.findMinPrice(minPrice);
    }

    // GET /api/products/42
    @GetMapping("/{id}")
    public ResponseEntity<Product> getById(@PathVariable Long id) {
        return service.findById(id)
                .map(ResponseEntity::ok)                        // 200 OK + JSON
                .orElseGet(() -> ResponseEntity.notFound().build()); // 404 Not Found
    }

    // POST /api/products (corps JSON transformé en objet Product)
    @PostMapping
    public ResponseEntity<Product> create(@RequestBody Product product) {
        Product saved = service.save(product);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved); // 201 Created
    }

    // DELETE /api/products/42
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        service.delete(id);
        return ResponseEntity.noContent().build();              // 204 No Content
    }
}

@RestController vs @Controller : @RestController renvoie directement des données (JSON) pour une API REST. Si tu veux renvoyer une page HTML côté serveur (avec un moteur de templates comme Thymeleaf), utilise @Controller et retourne le nom de la vue.

4. Persistance sans effort : Spring Data JPA

Spring Boot s'appuie directement sur les entités JPA (@Entity, @Id, relations) vues dans le cours précédent, mais supprime tout le code répétitif autour de l'EntityManager grâce aux interfaces JpaRepository.

Tu écris uniquement une interface : Spring génère toute la classe d'implémentation à l'exécution !

public interface ProductRepository extends JpaRepository<Product, Long> {

    // Requête générée automatiquement à partir du nom de la méthode !
    List<Product> findByNameContainingIgnoreCase(String motCle);
    List<Product> findByPriceLessThanOrderByPriceAsc(double maxPrice);

    // Ou requête JPQL personnalisée si besoin
    @Query("SELECT p FROM Product p WHERE p.quantity > :min")
    List<Product> findEnStock(@Param("min") int min);
}
  • CRUD gratuit : en héritant de JpaRepository<Product, Long>, tu obtiens immédiatement findAll(), findById(id) (qui renvoie un Optional), save(p) (INSERT ou UPDATE), deleteById(id), count() et existsById(id).
  • Transactions automatiques : place @Transactional sur une méthode de ton @Service pour que Spring ouvre, valide (commit) ou annule (rollback en cas d'exception) la transaction tout seul.

5. Configuration, DTO et bonnes pratiques

Toute la configuration du projet se centralise dans un seul fichier : src/main/resources/application.properties (ou application.yml).

# Port du serveur Tomcat embarqué
server.port=8080

# Connexion base de données H2 en mémoire
spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.username=sa
spring.datasource.password=

# Comportement Hibernate / JPA
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true

Les 3 réflexes professionnels à adopter dès le début

  • Séparer Entités et DTO : ne renvoie jamais directement une entité JPA sensible (ex. User avec son mot de passe haché) dans ton contrôleur ; utilise un record Java dédié comme DTO pour choisir exactement quels champs exposer.
  • Valider les entrées : annote les champs du DTO (@NotBlank, @Positive) et ajoute @Valid devant @RequestBody pour rejeter automatiquement les requêtes invalides (erreur HTTP 400).
  • Centraliser les erreurs : une classe annotée @RestControllerAdvice avec des méthodes @ExceptionHandler transforme proprement tes exceptions Java en réponses HTTP claires (404, 400, 409...) au lieu d'exposer une stacktrace au client.

Ne mets jamais tes vrais mots de passe de base de données dans Git ! En production, les identifiants passent par des variables d'environnement (ex. ${DB_PASSWORD}) et les mots de passe des utilisateurs sont toujours stockés hachés avec un sel (ex. BCrypt via Spring Security).

Méthodes et annotations indispensables

Méthode / AnnotationÀ quoi elle sert
@SpringBootApplication + SpringApplication.run(...)Point d'entrée : démarre Spring, le scan des composants et le serveur web embarqué.
@RestController / @Service / @RepositoryDéclarent les 3 couches de l'application pour que Spring les gère comme des beans.
@RequestMapping, @GetMapping, @PostMapping, @PutMapping, @DeleteMappingAssocient une URL et une méthode HTTP à une méthode Java du contrôleur.
@PathVariable / @RequestParam / @RequestBodyLisent une variable d'URL (/{id}), un paramètre (?q=...) ou le corps JSON d'une requête.
ResponseEntity.ok(obj) / .status(201).body(obj) / .notFound().build()Construisent une réponse HTTP complète avec le bon code de statut et le corps JSON.
repository.findAll() / findById(id)Récupèrent toutes les entités ou une entité par son ID (retourne un Optional<T>).
repository.save(entite)Insère une nouvelle entité ou met à jour une entité existante en base.
repository.deleteById(id) / existsById(id)Supprime une ligne par son ID ou vérifie son existence.
@TransactionalExécute une méthode de service dans une transaction (commit auto, rollback si erreur).
@Valid + @RestControllerAdvice / @ExceptionHandlerValident les données reçues et renvoient des messages d'erreur HTTP propres.

Spring Boot

Un framework Java qui accélère la création d'applications web et d'API en automatisant la configuration, le serveur web et la connexion à la base de données.

Auto-configuration

Mécanisme de Spring Boot qui observe les bibliothèques ajoutées à ton projet (ex. H2 + JPA) et configure automatiquement les connexions et composants nécessaires, sans XML.

Starter Spring Boot

Un « pack tout-en-un » de dépendances déjà compatibles entre elles (ex. spring-boot-starter-web embarque Tomcat, Spring MVC et Jackson pour le JSON).

Serveur embarqué

Le serveur HTTP (Tomcat par défaut) est inclus directement à l'intérieur de ton programme Java : plus besoin de l'installer séparément sur ta machine.

Inversion de Contrôle (IoC)

Principe où ce n'est plus ton code qui fabrique et orchestre ses objets avec new, mais le framework (Spring) qui prend la main sur leur création et leur cycle de vie.

Injection de Dépendances (DI)

Le fait que Spring fournisse automatiquement à une classe les objets dont elle a besoin (par exemple donner le Repository au Service via son constructeur).

Bean Spring

Un objet Java instancié, configuré et géré par le conteneur Spring (par défaut un singleton partagé dans l'application).

JSON (JavaScript Object Notation)

Un format texte léger en paires clé-valeur (ex. {"id": 1, "name": "Clavier"}), standard universel pour échanger des données entre un serveur et un client web ou mobile.

API REST

Une interface web qui expose des ressources via des URL claires (ex. /api/products/1) et les verbes HTTP (GET, POST, PUT, DELETE), généralement en JSON.

DTO (Data Transfer Object)

Un petit objet Java (souvent un record) qui sert uniquement à transporter les données entre le contrôleur et le client, sans exposer directement la structure interne de la base.

Hachage + Sel (Salt)

Transformer un mot de passe en une empreinte irréversible (hachage) en y ajoutant une chaîne aléatoire unique (le sel) pour empêcher les attaquants de retrouver le mot de passe même s'ils volent la base.
