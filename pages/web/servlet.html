Introduction aux servlets Java

Passe la souris surTouche les termes soulignés en pointillé pour afficher leur définition.

1. Qu'est-ce qu'une servlet ?

  • Nature : Un composant logiciel Java (une classe) exécuté côté serveur.
  • Le problème : Au départ, un serveur web ne savait envoyer que des fichiers statiques déjà présents sur son disque. Pour afficher une page sur mesure (ex. la météo en direct), il fallait un programme capable de fabriquer la réponse à la demande.
  • Le rôle : Intercepter la requête HTTP envoyée par le navigateur, calculer la réponse (lire une base de données, vérifier des identifiants) et renvoyer le résultat.

2. Pourquoi la servlet ne parle pas directement au client ?

Une servlet n'ouvre aucune socket et ne gère ni la connexion ni les ports réseau. C'est un conteneur comme Apache Tomcat qui reçoit les requêtes, les traduit en objets Java faciles à manipuler et les transmet à la servlet. Elle n'a plus qu'à exécuter son code et renvoyer la bonne page.

Ce que fait le conteneur :

  • Le conteneur écoute les requêtes brutes qui arrivent d'Internet via le protocole HTTP.
  • Il les traduit en deux objets Java : HttpServletRequest (la commande du client) et HttpServletResponse (la feuille blanche où écrire la réponse).
  • Il trouve la bonne servlet grâce à son routage URL, l'exécute, puis renvoie la réponse au client sur le réseau.

3. Le cycle de vie d'une servlet

Une servlet ne possède pas de méthode principale main(). C'est le serveur qui gère son cycle de vie, en 3 étapes :

  • 1. Initialisation (init()) : Exécutée une seule fois, à la création de la servlet. On y met ce qui coûte cher à préparer (ouvrir la connexion à la base de données, lire des fichiers de réglages).
  • 2. Service (service() / doGet() / doPost()) : Exécutée à chaque requête entrante. La servlet reçoit la demande, fait le calcul et écrit la réponse.
  • 3. Destruction (destroy()) : Appelée juste avant l'extinction du serveur pour fermer proprement les connexions et libérer la mémoire.
  • Le piège du multithread : La servlet est généralement un singleton (une seule instance en mémoire pour tout le monde). Chaque visiteur est pris en charge par un thread distinct.

4. Que produit une servlet ?

Une servlet renvoie un flux d'octets, quel que soit le format. C'est le développeur qui indique ce format avec le type MIME :

  • Du texte balisé (HTML) : Générer des pages complètes via response.getWriter() (avec le type text/html).
  • Des données structurées (API JSON / XML) : Envoyer des données aux applications mobiles ou à d'autres sites, avec application/json.
  • Des fichiers binaires : Transmettre directement des octets bruts (images à la volée, factures PDF, fichiers ZIP) via response.getOutputStream() avec le type application/pdf ou image/png.

Conteneur de servlets (ou gestionnaire de servlets)

Le moteur d'exécution (ex. Tomcat, Jetty). Il héberge la servlet, gère les connexions réseau et la sécurité, et appelle les méthodes de la servlet quand une requête arrive.

Requête HTTP

Le message envoyé par le navigateur pour demander une ressource (ex. « Donne-moi la page /produits » ou « Enregistre ce formulaire »).

Socket (Prise réseau)

Une extrémité de la connexion entre deux machines sur un réseau, identifiée par une adresse IP et un numéro de port (ex. 80 pour le web).

Protocole HTTP

Le protocole de la couche application qui sert à échanger des pages web, des images ou du texte.

Les principales méthodes HTTP sont :
• GET : Demander la récupération d'une ressource.
• POST : Envoyer des données pour créer ou modifier une ressource.
• PUT : Remplacer ou mettre à jour une ressource.
• DELETE : Supprimer une ressource.
• HEAD : Demander uniquement les en-têtes d'une ressource.
• PATCH : Appliquer une modification partielle à une ressource.

Routage URL

L'aiguillage du serveur : associer une adresse demandée (ex. /panier) au programme Java spécifique chargé de la traiter.

Singleton

Un composant dont il n'existe qu'un seul exemplaire actif en mémoire pour toute l'application, partagé par tous les utilisateurs.

Thread (Fil d'exécution)

Une suite d'instructions qui s'exécute en parallèle des autres, dans le même programme. Avec plusieurs threads, une tâche lente ne bloque pas les autres.

Type MIME (Content-Type)

L'étiquette standard qui indique au navigateur ce qu'il reçoit pour savoir comment l'ouvrir (ex. une vidéo, une page web ou un document PDF).
