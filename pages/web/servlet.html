Introduction aux Servlets Java

Passez la souris sur les termes soulignés en bleu pour afficher leur explication vulgarisée.

1. Qu'est-ce qu'une Servlet ?

  • Nature : Un composant logiciel Java (une classe) exécuté côté serveur.
  • Le problème d'origine : À l'origine, un serveur Web ne savait que délivrer des fichiers statiques existant déjà sur son disque dur. Pour afficher une page sur mesure (ex. la météo en direct), il fallait un programme capable de fabriquer la réponse à la demande.
  • Le rôle : Intercepter la requête HTTP envoyée par le navigateur, calculer la réponse (lire une base de données, vérifier des identifiants) et renvoyer le résultat.

2. Pourquoi la servlet ne parle pas directement au client ?

Une servlet ne s’occupe jamais directement de la connexion physique ni des ports réseau d'une machine, car elle n'ouvre aucune socket pour écouter les messages qui arrivent sur Internet. En réalité, elle confie entièrement cette tâche technique à un conteneur comme Apache Tomcat, qui se charge de capter les requêtes des internautes, de les traduire en objets Java faciles à manipuler, puis de les transmettre à la servlet pour qu'elle puisse simplement exécuter son code et renvoyer la bonne page web.

Le travail d'orchestration :

  • Le conteneur écoute les requêtes brutes qui arrivent d'Internet via le protocole HTTP.
  • Il traduit ces données texte en deux objets Java maniables : HttpServletRequest (la commande du client) et HttpServletResponse (la feuille blanche où écrire la réponse).
  • Il trouve la bonne servlet grâce à son routage URL, l'exécute, puis transforme la réponse en signaux réseau renvoyés au client.

3. Le cycle de vie d'une Servlet

Une servlet ne possède pas de méthode principale main(). C'est le serveur qui contrôle entièrement son existence à travers 3 étapes :

  • 1. Initialisation (init()) : Exécutée une seule et unique fois lors de la création de la servlet. Elle sert aux préparatifs lourds (ouvrir la connexion à la base de données, lire des fichiers de réglages).
  • 2. Service (service() / doGet() / doPost()) : Exécutée à chaque requête entrante. La servlet reçoit la demande, fait le calcul et écrit la réponse.
  • 3. Destruction (destroy()) : Appelée juste avant l'extinction du serveur pour fermer proprement les connexions et libérer la mémoire.
  • Le piège du multithread : La servlet est généralement un singleton (une seule instance en mémoire pour tout le monde). Chaque visiteur est pris en charge par un thread distinct.

4. Que produit une Servlet ?

Une servlet est neutre vis-à-vis du format de données : elle renvoie simplement un flux d'octets. C'est le développeur qui spécifie l'étiquette appelée type MIME :

  • Du texte balisé (HTML) : Générer des pages complètes via response.getWriter() (avec le type text/html).
  • Des données structurées (API JSON / XML) : Envoyer des données brutes pour les applications mobiles ou les sites modernes via application/json.
  • Des fichiers binaires : Transmettre directement des octets bruts (images à la volée, factures PDF, fichiers ZIP) via response.getOutputStream() avec le type application/pdf ou image/png.

Conteneur de servlets (ou gestionnaire de servlets)

Le moteur d'exécution (ex. Tomcat, Jetty). C'est lui qui héberge la servlet, gère les connexions Internet, applique la sécurité et lance les calculs au bon moment.

Requête HTTP

Le message envoyé par le navigateur pour demander une ressource (ex. « Donne-moi la page /produits » ou « Enregistre ce formulaire »).

Socket (Prise réseau)

Le point d'attache virtuel entre deux machines communicantes sur un réseau, composé d'une adresse IP et d'un numéro de port (ex. 80 pour le Web).

Protocole HTTP

Est un protocole de communication de la couche application qui permet l'échange de contenus en ligne, tels que des pages web, des images ou du texte.

Les principales méthodes HTTP sont :
• GET : Demander la récupération d'une ressource.
• POST : Envoyer des données pour créer ou modifier une ressource.
• PUT : Remplacer ou mettre à jour une ressource.
• DELETE : Supprimer une ressource.
• HEAD : Demander uniquement les en-têtes d'une ressource.
• PATCH : Appliquer une modification partielle à une ressource.

Routage URL

L'aiguillage du serveur : associer une adresse demandée (ex. /panier) au programme Java spécifique chargé de la traiter.

Singleton

Un composant dont il n'existe qu'un seul exemplaire actif en mémoire pour toute l'application, partagé par tous les utilisateurs.

Thread (Fil d'exécution)

Un thread distinct (ou fil d'exécution séparé) est une séquence d'instructions exécutée de manière autonome et indépendante par le processeur, au sein d'un même programme, afin de permettre l'exécution simultanée de plusieurs tâches sans bloquer les autres.

Type MIME (Content-Type)

L'étiquette standardisée qui indique au navigateur ce qu'il reçoit pour savoir comment l'ouvrir (ex. une vidéo, une page web ou un document PDF).
