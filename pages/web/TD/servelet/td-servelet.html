Les servlets

Passe la souris surTouche les termes soulignés en bleu pour afficher leur définition.

Introduction : Les annotations @WebServlet et @WebInitParam

  • Principe : L'annotation @WebServlet permet de déclarer une servlet Java sans repasser par le fichier de configuration web.xml. Elle permet de définir le nom, la description, les motifs d'URL (urlPatterns ou value) ainsi que des paramètres d'initialisation via @WebInitParam.
  • Exemple de déclaration : 
    @WebServlet(
    name = "BankAccountServlet",
    description = "Represents a Bank Account and it's transactions",
    urlPatterns = {"/account", "/bankAccount"},
    initParams = {
        @WebInitParam(name = "type", value = "savings"),
        @WebInitParam(name = "name", value = "a name")
    }
)
public class BankAccountServlet extends HttpServlet {
    // Implémentation de la servlet...
}
  • Attributs clés :
    • name : Le nom de la servlet.
    • urlPatterns : Tableau d'URL associées à la servlet (équivalent à value).
    • initParams : Liste de paramètres transmis à la servlet lors de son initialisation et accessibles via getInitParameter("nom").

0. Où ranger quoi - L'arborescence du projet

  • Principe : le code Java va dans src/main/java, les pages statiques (HTML, CSS, JSP) dans src/main/webapp. Le dossier WEB-INF est protégé : le navigateur ne peut pas y accéder directement.

  • Les tests : avec curl --noproxy "*", et toujours des guillemets autour de l'URL (sinon le & casse la commande).

1. Le cycle de vie - CycleServlet

  • Fichier : src/main/java/iut/nantes/cycle/CycleServlet.java
  • Énoncé : servlet sur /cycle-servlet qui redéfinit le constructeur, init(), init(ServletConfig), doGet, doPost, doPut, doPatch, doDelete et destroy, avec un affichage dans chacune.
  • Le principe : le conteneur instancie la servlet une seule fois, à la première requête. Elle reste en mémoire jusqu'à l'arrêt du serveur. Le cycle est : init() ->service() (qui aiguille vers doGet, doPost...) ->destroy().
  • Code : 
    @WebServlet(name = "cycleServlet", value = "/cycle-servlet")
public class CycleServlet extends HttpServlet {
    private String message;

    public CycleServlet() {
        System.out.println("Constructeur de CycleServlet !");
    }

    @Override
    public void init() {
        message = "Hello World!! Init sans param";
        System.out.println("Init sans param");
    }

    @Override
    public void init(ServletConfig config) throws ServletException {
        super.init(config);   // stocke la config ET appelle init()
        message = "Hello World!! Init avec param";
        System.out.println("Init avec param");
    }

    @Override
    public void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        System.out.println("doGet");
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<html><body><h1>" + message + "</h1></body></html>");
    }
    // doPost, doPut, doPatch, doDelete : même structure, avec leur println

    @Override
    public void destroy() {
        System.out.println("destroy");
        super.destroy();
    }
}
  • À retenir : sans super.init(config), le init() sans paramètre n'est jamais appelé et getServletConfig() renvoie null.
  • Test : 
    curl --noproxy "*" -X GET    "http://localhost:8888/demo/cycle-servlet"
curl --noproxy "*" -X POST   "http://localhost:8888/demo/cycle-servlet"
curl --noproxy "*" -X PUT    "http://localhost:8888/demo/cycle-servlet"
curl --noproxy "*" -X PATCH  "http://localhost:8888/demo/cycle-servlet"
curl --noproxy "*" -X DELETE "http://localhost:8888/demo/cycle-servlet"
    Dans podman logs tomcat_container : constructeur et init une seule fois, puis un seul doXxx par requête. destroy n'apparaît qu'à l'arrêt.

2. Les annotations @WebServlet et @WebInitParam - TestWebServlet

  • Fichier : src/main/java/iut/nantes/testweb/TestWebServlet.java
  • Énoncé : une servlet sur /webservlet1 et /webservlet2. En GET, elle affiche les paramètres dans la console, puis la valeur augmentée du pas (paramètres d'initialisation valeur et pas).
  • Le principe : les deux URL pointent vers la même instance, donc le compteur est partagé : 2, 4, 6, 8... d'une URL à l'autre.
  • Code : 
    @WebServlet(name = "testwebServlet",
        value = {"/webservlet1", "/webservlet2"},
        initParams = {
                @WebInitParam(name = "valeur", value = "0"),
                @WebInitParam(name = "pas", value = "2")
        })
public class TestWebServlet extends HttpServlet {
    private int valeur;
    private int pas;

    @Override
    public void init() {
        valeur = Integer.parseInt(getInitParameter("valeur"));
        pas = Integer.parseInt(getInitParameter("pas"));
    }

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
        System.out.println("-----------doGet-----------");
        Map<String, String[]> parametres = request.getParameterMap();
        parametres.forEach((cle, valeurs) ->
                System.out.println(cle + " = " + Arrays.toString(valeurs)));
                response.getWriter().println(cle + " = " + Arrays.toString(valeurs));

        valeur += pas;
        System.out.println("valeur = " + valeur + ", pas = " + pas);
        response.getWriter().println("valeur = " + valeur + ", pas = " + pas);
    }
}
  • À retenir : getParameterMap() renvoie une Map<String, String[]> : un paramètre répété (age=18&age=22) donne [18, 22]. Une servlet peut être appelée par plusieurs threads, donc valeur += pas n'est pas sûr en concurrence (solution : AtomicInteger ou synchronized).
  • Test : 
    curl --noproxy "*" "http://localhost:8888/demo/webservlet1"
curl --noproxy "*" "http://localhost:8888/demo/webservlet2"
curl --noproxy "*" "http://localhost:8888/demo/webservlet1?nom=Joe&age=18&age=22"

3. Un formulaire - Formulaire

  • Fichiers : src/main/java/iut/nantes/formulaire/Formulaire.java et src/main/webapp/formulaire.html (le CSS dans src/main/webapp/css/formulaire.css).
  • Énoncé : une page HTML avec un login et un mot de passe, et une servlet qui renvoie une page contenant les données reçues, en GET comme en POST.
  • Le principe : doGet et doPost appellent la même méthode privée. Les noms des champs HTML (name="login") sont les clés de getParameter(...).
  • Code Java : 
    @WebServlet(name = "formulaire", value = "/formulaire")
public class Formulaire extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        afficherLogin(request, response);
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        afficherLogin(request, response);
    }

    private void afficherLogin(HttpServletRequest request, HttpServletResponse response) throws IOException {
        String login = request.getParameter("login");
        String password = request.getParameter("password");
        if (login == null) { login = ""; }       // getParameter renvoie null si absent
        if (password == null) { password = ""; }

        response.setContentType("text/html;charset=UTF-8");
        PrintWriter out = response.getWriter();
        out.println("<html><body>");
        out.println("<h1>Informations reçues</h1>");
        out.println("<p>Login : " + login + "</p>");
        out.println("<p>Password : " + password + "</p>");
        out.println("</body></html>");
    }
}
  • Code HTML : 
    <form action="formulaire" method="POST">
  <input type="text" id="login" name="login">
  <input type="password" id="password" name="password">
  <button type="submit">Se connecter</button>
</form>
  • À retenir : action="formulaire" est une URL relative : elle garde le contexte /demo. Avec action="/formulaire", on perd le contexte et on obtient une 404. En GET, le mot de passe apparaît dans l'URL : on utilise POST pour les données sensibles.
  • Test : 
    curl --noproxy "*" -i -X POST -d "login=admin" -d "password=secret" "http://localhost:8888/demo/formulaire"
curl --noproxy "*" -i "http://localhost:8888/demo/formulaire?login=admin&password=secret"

4. Une redirection - FormulaireRedirection

  • Fichiers : src/main/java/iut/nantes/redirectionform/FormulaireRedirection.java et src/main/webapp/formulaireRedirection.html (même formulaire, avec action="formulaireRedirection").
  • Énoncé : si le login n'est pas Joe ou le mot de passe n'est pas JoJo44, le client est renvoyé vers le formulaire d'origine.
  • Le principe : une redirection est une réponse 302 avec un header Location. C'est le client qui refait ensuite une requête GET vers la nouvelle URL. L'origine se lit dans le header Referer.
  • Code : 
    @WebServlet(name = "formulaireRedirection", value = "/formulaireRedirection")
public class FormulaireRedirection extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request,HttpServletResponse response) throws ServletException, IOException {
        authenticate(request, response);
    }

    @Override
    protected void doPost(HttpServletRequest request,HttpServletResponse response)throws ServletException, IOException {
        authenticate(request, response);
    }
    /*
     * Méthode privée qui récupère les données envoyées
     * par le formulaire et construit une page HTML.
     *
     * Elle est appelée par doGet() et doPost().
     */
    private void authenticate(HttpServletRequest request, HttpServletResponse response) throws IOException {

        String login = request.getParameter("login");
        String password = request.getParameter("password");

        /*
         * Vérifie les identifiants saisis.
         *
         * "Joe".equals(login) vérifie que le login est "Joe".
         * "JoJo44".equals(password) vérifie que le mot de passe est "JoJo44".
         *
         * L'opérateur || signifie "OU" :
         * si le login OU le mot de passe est incorrect,
         * l'authentification échoue.
         *
         * L'utilisation de equals() sur une chaîne constante
         * évite une NullPointerException si le paramètre vaut null.
         */
        if (!"Joe".equals(login) || !"JoJo44".equals(password)){
            String referer = request.getHeader("Referer");
            if (referer != null) {
                // URL de la page d'origine (le formulaire d'où vient l'utilisateur)..
                response.sendRedirect(referer);
            } else {
                response.sendRedirect("index.jsp");
            }
            return;
        }

        response.setContentType("text/html;charset=UTF-8");

        PrintWriter out = response.getWriter();

        out.println("<html<");
        out.println("<body<");
        out.println("<h1<Welcome</h1<");
        out.println("<p<Login : " + login + "</p<");
        out.println("<p<Password : " + password + "</p<");
        out.println("</body<");
        out.println("</html<");
    }
}
  • À retenir : "Joe".equals(login) (constante à gauche) évite un NullPointerException si le paramètre est absent. Le return après sendRedirect est nécessaire pour ne pas continuer à écrire la réponse. Le Referer est envoyé par le client : il peut manquer, d'où le repli.
  • Test : 
    curl --noproxy "*" -i -d "login=Joe" -d "password=faux" \
  -H "Referer: http://localhost:8888/demo/formulaireRedirection.html" \
  "http://localhost:8888/demo/formulaireRedirection"
# attendu : HTTP/1.1 302 et "Location: ...formulaireRedirection.html"

5. Les cookies - Pré-remplir le login

  • Fichiers : src/main/java/iut/nantes/persistanceform/Login.java (le formulaire) et src/main/java/iut/nantes/persistanceform/PersistanceAuth.java (l'authentification). Ici, pas de fichier HTML : le formulaire est généré par la servlet.
  • Énoncé : si l'authentification réussit puis que le formulaire est consulté à nouveau, le login doit rester pré-rempli.
  • Le principe : HTTP n'a pas d'état. Un cookie est un petit texte que le serveur envoie au client (header Set-Cookie) et que le client renvoie à chaque requête suivante. La servlet d'authentification crée le cookie, la servlet du formulaire le lit.
  • Création (PersistanceAuth), après vérification réussie : 
    @WebServlet(name = "persistanceAuth", value = "/persistance-authenticate")
public class PersistanceAuth extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)  throws ServletException , IOException{
        authenticate(request,response);
    }
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)  throws ServletException , IOException{
        authenticate(request,response);
    }

    private void authenticate(HttpServletRequest request , HttpServletResponse response) throws IOException{
        String login = request.getParameter("login");
        String password = request.getParameter("password");

        if (!"Joe".equals(login) || !"JoJo44".equals(password)){
            System.out.println("login ou password err");
            String referer = request.getHeader("Referer");
            if (referer != null) {
                response.sendRedirect(referer);
            } else {
                response.sendRedirect("index.jsp");
            }
            return;
        }
        Cookie cookie = new Cookie("login", login);

        // Définit la durée de vie du cookie à une heure.
        cookie.setMaxAge(60 * 60);

        // Rend le cookie accessible sur tous les chemins de l'application
        // qui correspondent à ce chemin de cookie.
        cookie.setPath("/");

        // Ajoute le cookie à la réponse HTTP.
        // Le navigateur pourra le conserver et le renvoyer lors
        // des requêtes suivantes, tant qu'il est valide.
        response.addCookie(cookie);

        response.setContentType("text/html;charset=UTF-8");

        PrintWriter out = response.getWriter();

        out.println("<html<");
        out.println("<body<");
        out.println("<h1<Welcome</h1<");
        out.println("<p<Login : " + login + "</p<");
        out.println("<p<Password : " + password + "</p<");
        out.println("</body<");
        out.println("</html<");
    }
}

6. Les sessions - Garder l'utilisateur connecté côté serveur

  • Fichiers : dans src/main/java/iut/nantes/session/ : Login.java (le formulaire, identique à celui des cookies, avec action="session-authenticate"), Authenticate.java et SessionPage.java.
  • Énoncé : si l'authentification réussit, rediriger vers une autre servlet qui affiche le login.
  • Le principe : les données restent côté serveur, dans la session. Le navigateur ne reçoit qu'un cookie JSESSIONID, créé par Tomcat, qui identifie sa session.

  • Écriture (Authenticate, /session-authenticate) : 
    // ... même vérification du login et du mot de passe que dans la partie Persistance

/*
  * Servlet chargée de vérifier les identifiants de l'utilisateur.
  *
  * Si les identifiants sont corrects :
  * - un cookie mémorise le login dans le navigateur ;
  * - une session HTTP conserve le login côté serveur ;
  * - l'utilisateur est redirigé vers la page privée.
  */
@WebServlet(name = "sessionAuthenticate", value = "/session-authenticate")
public class Authenticate extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request,HttpServletResponse response) throws ServletException, IOException {
        authenticate(request, response);
    }

    @Override
    protected void doPost(HttpServletRequest request,HttpServletResponse response) throws ServletException, IOException {
        authenticate(request, response);
    }

    private void authenticate(HttpServletRequest request, HttpServletResponse response) throws IOException, ServletException {
        String login = request.getParameter("login");
        String password = request.getParameter("password");

        if (!"Joe".equals(login) || !"JoJo44".equals(password)){
            System.out.println("login ou password err");
            String referer = request.getHeader("Referer");
            if (referer != null) {
                response.sendRedirect(referer);
            } else {
                response.sendRedirect("index.jsp");
            }
            return;
        }

        Cookie cookie = new Cookie("login", login);

        cookie.setMaxAge(60 * 60);
        cookie.setPath("/");
        response.addCookie(cookie);

        response.setContentType("text/html;charset=UTF-8");

        HttpSession session = request.getSession();// récupère ou CRÉE la session
        session.setAttribute("login", login); // Stocke le login dans la session sous la clé "login"
        response.sendRedirect("session-page");// relative : garde /demo

        response.sendRedirect("session-page");
    }
}
  • Lecture (SessionPage, /session-page) : 
    @WebServlet(name="sessionPage",value="/session-page")
public class SessionPage extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest request , HttpServletResponse response) throws ServletException, IOException{
        HttpSession session = request.getSession(false);
        if (session != null && session.getAttribute("login") != null  && session.getAttribute("password") != null) {

            String login = (String) session.getAttribute("login");
            String password = (String) session.getAttribute("password");

            response.setContentType("text/html;charset=UTF-8");

            PrintWriter out = response.getWriter();

            out.println("<!DOCTYPE html<");
            out.println("<html<");
            out.println("<head<");
            out.println("<title<session</title<");
            out.println("</head<");

            out.println("<body<");

            out.println("<h1<Welcome</h1<");
            out.println("<p<"+login+"</p<");
            out.println("<p<"+password+"</p<");

            out.println("</body<");
            out.println("</html<");

        }else {
            // utilisateur non connecté
            response.sendRedirect("session-login");
            return;
        }

    }

}
  • À retenir :
    • getSession() crée la session si besoin, getSession(false) renvoie null si elle n'existe pas : c'est ce qui permet de savoir si l'utilisateur est connecté.
    • getAttribute renvoie un Object : il faut le convertir ((String)).
    • Redirection après un POST : si l'utilisateur rafraîchit la page, il ne renvoie pas le formulaire.
    • Une session expire après 30 minutes d'inactivité par défaut (setMaxInactiveInterval) et se termine avec session.invalidate().
  • Test : 
    curl --noproxy "*" -i -c cj.txt -d "login=Joe" -d "password=JoJo44" "http://localhost:8888/demo/session-authenticate"  # 302 + Set-Cookie: JSESSIONID
curl --noproxy "*" -i -b cj.txt "http://localhost:8888/demo/session-page"   # 200, page Welcome
curl --noproxy "*" -i "http://localhost:8888/demo/session-page"             # 302 vers session-login

Servlet

Une classe Java qui hérite de HttpServlet et répond à des requêtes HTTP (GET, POST...) sur un serveur web.

  • Elle est instanciée une seule fois et peut être appelée par plusieurs threads.

Conteneur web

Le moteur qui crée les servlets, appelle leurs méthodes et gère leur cycle de vie. Ici, c'est Tomcat.

Redirection HTTP

Le serveur répond avec un code 30X (ici 302) et l'adresse dans le header Location. Le client consulte alors la nouvelle URL.

Header Referer

L'URL de la page d'où vient la requête, envoyée par le client.

  • Il peut être absent : toujours prévoir un repli.

Cookie

Un court texte envoyé par le serveur (Set-Cookie), que le client renvoie aux requêtes suivantes vers le même domaine.

  • Il permet de contourner l'absence d'état du protocole HTTP.

Session

Un espace de données conservé côté serveur pour un utilisateur. Le client ne garde que l'identifiant (cookie JSESSIONID).
