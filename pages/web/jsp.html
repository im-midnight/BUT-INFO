JSP (Jakarta Server Pages)

Passe la souris surTouche les termes soulignés en pointillé pour afficher leur définition.

1. Pourquoi les JSP ?

Avec une servlet seule, écrire une page HTML entière est vite pénible : on doit tout concaténer dans des appels out.println("<h1>...</h1>"), et la logique métier se retrouve mélangée à l'affichage.

Une JSP (Jakarta Server Page) inverse le point de vue : on écrit une page HTML normale, dans laquelle on glisse uniquement les morceaux dynamiques (variables, boucles, conditions).

Dans une architecture MVC, la répartition des rôles est stricte :

  • Modèle (DAO / objets métier) : gère les données.
  • Contrôleur (Servlet) : reçoit la requête HTTP, appelle le modèle et choisit la suite.
  • Vue (JSP) : se contente d'afficher les données préparées par la servlet.

2. Cycle de vie : une JSP est une servlet

Le navigateur ne reçoit jamais le code Java d'une JSP. À la toute première visite sur mon.jsp, le conteneur web (Tomcat, via son moteur Jasper) exécute automatiquement une chaîne en 6 étapes :

  1. Traduction (transpilation) : mon.jsp est traduit en un fichier source Java mon_jsp.java qui implémente l'interface HttpJspPage (fille de JspPage, elle-même fille de Servlet).
  2. Compilation : mon_jsp.java est compilé en bytecode (mon_jsp.class).
  3. Chargement et instanciation : la JVM charge la classe et crée une seule instance de cette servlet.
  4. Initialisation : jspInit() est appelée une unique fois au démarrage de la JSP.
  5. Traitement des requêtes : à chaque requête client, le conteneur appelle _jspService(request, response) et renvoie le HTML généré.
  6. Destruction : à l'arrêt de l'application, jspDestroy() libère les ressources.

Comme tout s'exécute côté serveur, une erreur dans une JSP se débogue dans les logs du serveur (Tomcat), pas dans la console du navigateur.

3. Les balises JSP essentielles

Une page JSP combine du HTML statique avec cinq familles d'éléments de script et de directives :

SyntaxeNomRôle
<%@ page ... %>Directive pageConfigure la JSP : encodage (contentType, pageEncoding), import de classes Java, errorPage, isELIgnored.
<%@ include file="..." %>Directive includeCopie-colle un autre fichier dans la JSP au moment de la compilation (partage les variables locales).
<%@ taglib uri="..." prefix="..." %>Directive taglibImporte une bibliothèque de balises comme la JSTL.
<% ... %>ScriptletCode Java exécuté à chaque requête dans _jspService(). Peut être fragmenté autour du HTML.
<%= ... %>ExpressionÉvalue une expression Java et l'affiche directement dans le HTML (sans point-virgule).
<%! ... %>DéclarationDéclare un attribut ou une méthode au niveau de la classe (hors de _jspService()).
<%-- ... --%>Commentaire JSPIgnoré à la compilation : invisible dans le code source reçu par le navigateur (contrairement à <!-- -->).

Exemple minimal avec directive, scriptlet et expression

<%@ page language="java" contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<!DOCTYPE html>
<html lang="fr">
<head><meta charset="UTF-8"><title>Liste JSP</title></head>
<body>
  <h1>Ma liste de 3 éléments</h1>
  <ul>
    <% for (int i = 1; i <= 3; i++) { %>
      <li>Élément <%= i %></li>
    <% } %>
  </ul>
</body>
</html>

Attention aux déclarations <%! ... %> : comme la JSP est compilée en une seule instance de servlet partagée par tous les clients, une variable déclarée dans <%! %> est partagée entre tous les utilisateurs. Ne jamais y stocker de données propres à un visiteur !

4. Objets implicites et portées (scopes)

Dans un scriptlet ou une expression, neuf objets implicites existent déjà sans que tu aies à les déclarer. Les 5 que tu utiliseras 90 % du temps sont request, response, session, application et out (plus pageContext, config, page et exception sur une page d'erreur).

Les 4 niveaux de portée (scopes)

Pour faire circuler des données entre pages et servlets, on les stocke comme attributs dans l'une des quatre portées imbriquées, de la plus courte à la plus longue :

ScopeObjet JSPDurée de vieUsage typique
pagepageContextUniquement la JSP courante.Variable temporaire de calcul sur la page.
requestrequestUne seule requête HTTP (survit au forward).Transmettre une liste d'une Servlet vers une JSP.
sessionsessionToute la visite d'un même utilisateur.Login connecté, panier d'achat.
applicationapplicationToute la vie du serveur, pour tous les clients.Configuration globale, compteur global de visites.

5. Relier Servlet et JSP en MVC (Forward vs Redirect)

C'est le schéma le plus important de R3.01 : l'utilisateur appelle toujours une servlet, jamais une JSP qui ferait elle-même des requêtes au DAO.

  1. Lecture (GET) : la servlet récupère les données du DAO, les pose dans la requête avec request.setAttribute("products", liste), puis passe la main en interne à la JSP avec un forward.
  2. Modification (POST) : un formulaire HTML dans la JSP envoie une action en POST vers la servlet. La servlet modifie les données puis renvoie une redirection (sendRedirect) vers le GET pour éviter qu'un rafraîchissement ne renvoie deux fois le formulaire.
// Dans la Servlet (Contrôleur)
protected void doGet(HttpServletRequest req, HttpServletResponse resp)
        throws ServletException, IOException {
    req.setAttribute("products", productDao.getAll());
    // Transfert interne : l'URL ne change pas, les attributs de req sont conservés
    req.getRequestDispatcher("/JSP/Products/products_view.jsp")
       .forward(req, resp);
}

protected void doPost(HttpServletRequest req, HttpServletResponse resp)
        throws IOException {
    int id = Integer.parseInt(req.getParameter("id"));
    productDao.incrementQuantity(id);
    // Redirection HTTP (302) : nouvelle requête GET propre
    resp.sendRedirect(req.getContextPath() + "/products/controller");
}

Inclusion statique vs dynamique

  • <%@ include file="header.jsp" %> (statique) : fusionné à la compilation. Plus rapide, partage les variables Java locales. Idéal pour un en-tête ou pied de page fixe.
  • <jsp:include page="nav.jsp" /> (dynamique) : exécuté à chaque requête. Ne partage pas les variables locales, mais accepte des paramètres via <jsp:param> et suit les changements dynamiques.
  • <jsp:forward page="erreur.jsp" /> : arrête la JSP courante et transfère le contrôle côté serveur à une autre page (en conservant request).

6. Écrire des vues propres : EL, JSTL et JavaBeans

Mélanger de gros blocs <% ... %> dans du HTML rend vite les pages illisibles. Pour supprimer le code Java des vues, JSP propose trois outils complémentaires :

1. Les JavaBeans et les actions standard

Un JavaBean est une simple classe Java dans un package nommé (jamais le default package) avec : des attributs private, un constructeur public sans paramètre et des getters/setters publics. Les balises <jsp:useBean>, <jsp:getProperty> et <jsp:setProperty property="*" /> permettent d'instancier et de remplir automatiquement un bean depuis un formulaire (si les noms des champs HTML correspondent aux attributs Java, avec conversion automatique vers int, double, boolean...).

2. L'Expression Language (EL) : ${ ... }

L'EL remplace les expressions <%= ... %> et les casts pénibles. Écrire ${product.name} cherche automatiquement l'attribut product dans l'ordre page → request → session → application, puis appelle getName().

  • Objets EL courants : ${param.recherche} (paramètre d'URL/formulaire), ${sessionScope.login}, ${requestScope.products}, ${cookie.login.value}, ${pageContext.request.contextPath} (préfixe de l'application).
  • Opérateurs pratiques : empty liste (vrai si null, chaîne vide ou collection vide), ternaire ${age >= 18 ? 'Majeur' : 'Mineur'}, comparaisons (==/eq, </lt, &&/and).

3. La JSTL (bibliothèque standard de balises)

La JSTL remplace les boucles for et les if Java par des balises propres de type XML. On déclare la bibliothèque core en haut de la JSP, puis on utilise le préfixe c: (et fmt: pour l'i18n et le formatage des dates/devises).

<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<%@ taglib uri="jakarta.tags.core" prefix="c" %>
<%-- (Anciennes versions Java EE / Tomcat < 10 : uri="http://java.sun.com/jsp/jstl/core") --%>

<ul>
  <c:forEach items="${requestScope.products}" var="product" varStatus="st">
    <li class="${st.index % 2 == 0 ? 'pair' : 'impair'}">
      <c:out value="${product.name}" /> — ${product.price} €
      <c:if test="${product.price < 30}">
        <strong>(Promo !)</strong>
      </c:if>
    </li>
  </c:forEach>
</ul>

Utiliser <c:out value="${...}" /> échappe automatiquement les caractères HTML (<, >) : cela protège ta page contre les failles XSS lorsqu'on affiche un texte saisi par un utilisateur.

JSP (Jakarta Server Pages)

Un fichier HTML enrichi de balises spéciales qui permettent d'insérer des données calculées par Java. Le serveur le transforme automatiquement en servlet avant de l'exécuter.

MVC (Modèle - Vue - Contrôleur)

Une façon d'organiser une application en 3 rôles séparés : le Modèle gère les données, le Contrôleur orchestre les actions et la Vue s'occupe uniquement de l'affichage.

DAO (Data Access Object)

Une classe dédiée uniquement à lire, ajouter, modifier ou supprimer des données (en mémoire ou en base de données), pour isoler le reste du code du stockage.

Conteneur web (ex. Tomcat)

Le moteur serveur qui héberge l'application web, traduit les JSP en servlets, gère les requêtes HTTP et appelle les bonnes méthodes.

Transpilation (traduction)

Transformer automatiquement un fichier écrit dans un format (ici .jsp) en un fichier source dans un autre langage (ici du code Java .java) avant de le compiler.

Bytecode (fichier .class)

Le code intermédiaire produit par le compilateur Java. Il n'est pas lisible par un humain, mais compris par la JVM sur n'importe quel système d'exploitation.

JVM (Java Virtual Machine)

Le programme qui exécute le bytecode Java sur ta machine ou sur le serveur.

Directive JSP (<%@ ... %>)

Une consigne donnée au serveur au moment où il traduit la JSP en servlet (ex. quels packages Java importer, quel encodage UTF-8 utiliser).

Scriptlet (<% ... %>)

Un bloc de code Java collé directement dans une JSP et exécuté à chaque affichage de la page. Aujourd'hui on préfère le remplacer par EL et JSTL.

Objet implicite

Un objet Java que le serveur prépare et met automatiquement à disposition dans toute JSP (comme request, session ou out), sans avoir besoin de le déclarer.

Scope (portée)

La durée de vie et la visibilité d'une donnée stockée côté serveur : juste cette page (page), le temps d'une requête (request), le temps de la visite d'un utilisateur (session) ou pour tout le site (application).

Forward (transfert interne)

Le serveur passe le relais d'une servlet à une JSP en coulisses, sans prévenir le navigateur. L'URL affichée ne change pas et les données de request sont conservées.

Redirection HTTP (sendRedirect)

Le serveur répond au navigateur « va plutôt voir à cette autre adresse » (code 302). Le navigateur fait alors une toute nouvelle requête, ce qui change l'URL et vide les attributs de l'ancienne requête.

JavaBean

Une classe Java qui respecte 3 règles simples pour être manipulée facilement par les outils JSP : un constructeur vide public, des attributs privés et des getters/setters publics.

EL (Expression Language)

Une notation courte entre ${ } qui permet de lire facilement des attributs, propriétés d'objets ou paramètres dans une JSP sans écrire de Java.

JSTL (Jakarta Standard Tag Library)

Une boîte à outils de balises prêtes à l'emploi (<c:forEach>, <c:if>, <c:out>...) qui permet de faire des boucles et conditions proprement dans une JSP.

i18n (Internationalisation)

Adapter automatiquement un site à la langue et au pays du visiteur (textes traduits, format des dates et des devises). « i18n » vient des 18 lettres entre le i et le n.

XSS (Cross-Site Scripting)

Une faille de sécurité qui permet à un attaquant d'injecter du code JavaScript malveillant (ex. <script>...</script>) dans une page web affichée à d'autres utilisateurs.
