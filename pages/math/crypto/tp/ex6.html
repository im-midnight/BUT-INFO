Exercice 6 : RSA et signature numérique

Passe la souris surTouche les termes soulignés en bleu pour afficher leur définition.

Principe général

Dans le cryptosystème RSA, chaque personne possède un couple de clés : une clé publique $(n, e)$ que tout le monde peut connaître, et une clé privée $d$ qu'elle seule connaît. Ce qu'on chiffre avec l'une se déchiffre avec l'autre :

$$ \left(m^{e}\right)^{d} \equiv m \pmod n \qquad \text{et} \qquad \left(m^{d}\right)^{e} \equiv m \pmod n $$
  • Confidentialité : on chiffre avec la clé publique du destinataire, lui seul peut déchiffrer.
  • Signature : on chiffre l'empreinte du message avec sa clé privée, tout le monde peut vérifier avec la clé publique.
Dans le sujet : c'est Bernard qui signe son message. Ici les rôles sont inversés (Alice signe, Bernard vérifie) : le mécanisme est strictement le même.

6.1 Génération de la clé : key_creation()

  • Principe : on choisit deux nombres premiers distincts $p$ et $q$ (entre le 26e et le 1000e nombre premier, donc $\geq 101$ pour que $n = pq > 10\,000$), puis on calcule : $$n = p \cdot q \qquad \varphi(n) = (p-1)(q-1)$$
  • Clé publique $(n, e)$ : $e$ est choisi premier avec $\varphi(n)$ ($\text{pgcd}(e, \varphi(n)) = 1$), ce qui le rend inversible modulo $\varphi(n)$.
  • Clé privée $d$ : l'inverse de $e$ modulo $\varphi(n)$, trouvé par l'algorithme d'Euclide étendu : $$e \cdot d \equiv 1 \pmod{\varphi(n)}$$ 
from rsa_math import *

def key_creation() -> tuple:

    mini = n_premier(26)
    maxi = n_premier(1000)

    p = chercher_premier(mini, maxi)
    q = chercher_premier(mini, maxi)
    print("p :",p)
    print("q :",q)

    while q == p:
        q = chercher_premier(mini, maxi)
        
    n = p * q
    phi = (p-1)*(q-1)
    e = chercher_premier_avec(phi, phi)
    print("e :",e)
    while e <= 1:
        e = chercher_premier_avec(phi, phi)
    print("phi :",phi)
    d = inverse_mod_euclide(e, phi)
    return (n, e, d)

key_creation() ne fait aucun calcul lui-même : tout repose sur six fonctions du fichier rsa_math.py, plus pow de Python pour le chiffrement. Chacune traduit une idée mathématique du cours.

1. est_premier(n) : test de primalité

Si $n$ n'est pas premier, son plus petit diviseur premier est inférieur ou égal à $\sqrt{n}$. Il suffit donc de tester les diviseurs $2, 3, 4, \ldots$ tant que $\text{div}^2 \leq n$, soit environ $\sqrt{n}$ divisions au maximum.

def est_premier(n:int) -> bool:
    div = 2
    if n == 0 or n==1:
        return False
    
    while div*div <= n:
        if n % div == 0:
            return False        
        div += 1
    return True

2. n_premier(n) : le $n$-ième nombre premier

On parcourt les entiers à partir de $2$, on compte ceux qui sont premiers, et on s'arrête quand on en a compté $n$. Le 26e nombre premier vaut $101$ : avec deux premiers distincts $p, q \geq 101$, on a $n = pq \geq 101 \times 103 = 10\,403 > 9\,999$, donc tous les paquets de 4 chiffres sont inférieurs à $n$.

def n_premier(n):
    i=2
    nbr = 0
    while nbr < n:
        if(est_premier(i)):
            nbr+=1
        i+=1
    return i-1

3. chercher_premier(mini, maxi) : un premier aléatoire

On tire un entier $n$ au hasard dans l'intervalle. S'il est premier, on le renvoie. Sinon on regarde $n+1, n-1, n+2, n-2, \ldots$ jusqu'à trouver un nombre premier. Les nombres premiers sont assez fréquents (environ un entier sur $\ln n$), donc la recherche s'arrête vite. La fonction renvoie $0$ si l'intervalle ne contient aucun premier.

def chercher_premier(mini:int, maxi:int) -> int:
    n = randint(mini, maxi)
    if est_premier(n):
        return n
    
    i = 1
    while n - i >= mini or n + i <= maxi:
        if n+i <= maxi and est_premier(n + i):
            return n + i
        if n-i >= mini and est_premier(n - i):
            return n - i
        i += 1
    return 0

4. sont_premiers(a, b) : algorithme d'Euclide

Le pgcd se calcule avec la relation $\text{pgcd}(a, b) = \text{pgcd}(b,\ a \bmod b)$, répétée jusqu'à obtenir un reste nul. Deux entiers sont premiers entre eux exactement quand ce pgcd vaut $1$.

def sont_premiers(a:int, b:int) -> bool:
    while b != 0:
        a, b = b, a % b
    return a == 1

5. chercher_premier_avec(n, maxi) : choisir $e$

On cherche $e$ tel que $\text{pgcd}(e, \varphi(n)) = 1$. C'est exactement la condition pour que $e$ soit inversible modulo $\varphi(n)$, donc pour que $d$ existe. Même principe que chercher_premier : tirage aléatoire, puis recherche autour du tirage avec sont_premiers.

def chercher_premier_avec(n:int, maxi:int) -> int:
    x = randint(1, maxi)
    if sont_premiers(x,n):
        return x
    i = 1
    while x - i >= n or x + i <= maxi:
        if x + i <= maxi and sont_premiers(x + i, n):
            return x + i
        if x - i >= 1 and sont_premiers(x - i, n):
            return x - i
        i += 1
    return 0
Détail : la valeur $1$ est toujours première avec $\varphi(n)$ mais ne chiffre rien ($m^1 = m$). C'est pourquoi key_creation() contient while e <= 1 : si la fonction renvoie $1$ (ou $0$ en cas d'échec), un nouvel $e$ est tiré. Dans la condition de la boucle, x - i >= n n'est jamais vraie quand maxi = n (puisque $x \leq n$) : la recherche vers le bas n'est donc effectuée que tant que x + i <= maxi. Cela ne change pas la correction grâce à ce nouveau tirage.

6. inverse_mod_euclide(a, b) : calcul de $d$

L'algorithme d'Euclide étendu construit, à chaque division, des coefficients $u_i$ et $v_i$ tels que :

$$ r_i = a\,u_i + b\,v_i $$

Quand le dernier reste non nul vaut $1$ (donc $\text{pgcd}(a, b) = 1$), on a $au + bv = 1$, c'est-à-dire $au \equiv 1 \pmod b$ : $u$ est l'inverse de $a$ modulo $b$. On renvoie u0 % b pour obtenir une valeur positive, et None si $a$ n'est pas inversible.

def inverse_mod_euclide(a:int, b:int):
    r0, r1 = a, b
    u0, u1 = 1, 0
    v0, v1 = 0, 1
    while r1 != 0:
        q = r0 // r1
        r0, r1 = r1, r0 - q * r1
        u0, u1 = u1, u0 - q * u1
        v0, v1 = v1, v0 - q * v1

    if r0 == 1:
        return u0 % b

    return None

6.2 Chiffrer et déchiffrer un entier

  • Chiffrement : $c = m^{e} \bmod n$
  • Déchiffrement : $m = c^{d} \bmod n$, valable pour $0 \leq m < n$.
  • Pourquoi ça marche : $c^d \equiv m^{ed}$ et $ed = 1 + k\,\varphi(n)$. Par le théorème d'Euler, $m^{\varphi(n)} \equiv 1 \pmod n$ (si $m$ est premier avec $n$), donc $m^{ed} \equiv m \cdot (m^{\varphi(n)})^k \equiv m \pmod n$.
  • En Python : pow(m, e, n) fait l'exponentiation modulaire rapide, sans calculer l'énorme nombre $m^e$.

6.3 et 6.4 Message long : découpage en paquets de 4 chiffres

  • Pourquoi 4 chiffres ? Chaque paquet est un entier entre $0$ et $9999$. Comme $n > 10\,000$, chaque paquet est bien strictement inférieur à $n$ et ne perd donc aucune information lors du calcul modulo $n$.
  • Chiffrement : on complète le nombre avec des $0$ à gauche pour que sa longueur soit un multiple de 4, on découpe en paquets $c_i$ et on calcule $c_i^{\,\text{exposant}} \bmod n$ pour chacun. Le résultat est une liste d'entiers.
  • Déchiffrement : on déchiffre chaque élément de la liste puis on recolle les paquets avec res = res * 10000 + paquet.
  • Remarque : les fonctions prennent l'exposant en paramètre (nommé e dans encryption et d dans decryption). Pour une signature on les utilise donc "à l'envers", voir 6.5.
import math
def encryption_int(n,e,m) -> int:
    return pow(m,e,n)

def decryption_int(n,d,c) -> int:
    return pow(c,d,n)

def encryption(n,e,msg) -> str:
    res=[]
    s = str(msg)
    while len(s) % 4 != 0:
        s = "0" + s
    for i in range(0, len(s), 4):
        bits = int(s[i:i+4])
        res.append(encryption_int(n,e,bits))
    return res


def decryption(n,d,msg) -> int:
    res = 0
    for c in msg:
        res = res * 10000 + decryption_int(n,d,c)
    return res

6.5 Message signé : Alice envoie $(m,\ h(m)^d)$

La clé publique d'Alice $(n, e)$ est connue de tout le monde, seule Alice connaît $d$. Alice envoie à Bernard son message $m$ accompagné de $h(m)^d$, et Bernard vérifie avec $e$.

a. Calcul de l'empreinte

import hashlib as hash
message="Je déclare être bien l'auteur de ce texte par lequel je te déclare ma flamme. Bien romantiquement. Alice"
message_utf8=message.encode()
message_hash=hash.sha256(message_utf8).hexdigest()    # SHA-256, en hexadécimal
number_message_hash=int(message_hash,16)              # conversion en entier base 10
  • Message utilisé : « Je déclare être bien l'auteur de ce texte par lequel je te déclare ma flamme. Bien romantiquement. Alice »
  • Empreinte SHA-256 (hexadécimal) : 
    0adbd6e87ad369a21e80c5ea2b6747ec9dc08c5d402ea5900d013aa6d173a32c
  • Empreinte convertie en entier base 10 ($h(m)$, 76 chiffres) : 
    4911551234380039706606657750189788292486623056763336247687767279071288075052

b. Chiffrement de l'empreinte : ce qu'Alice envoie

  • Alice chiffre l'empreinte avec sa clé privée $d$ (et non avec $e$) : paquet par paquet, $$S_i = c_i^{\,d} \bmod n$$ où les $c_i$ sont les paquets de 4 chiffres de $h(m)$. La signature est la liste $S = [S_1, \dots, S_{19}]$.
  • Alice envoie à Bernard le couple $(m, S)$ : le message $m$ en clair (il n'est pas confidentiel) et la signature $S$ (le chiffrement de l'empreinte).

c. Vérification par Bernard

  • Bernard reçoit $(m', S)$. Il fait deux calculs indépendants :
    1. Il hache lui-même le message reçu : $h(m')$.
    2. Il déchiffre la signature avec la clé publique d'Alice : $S_i^{\,e} \bmod n$ pour chaque paquet, puis il recolle les paquets pour obtenir un entier $h_{\text{déchiffré}}$.
  • Il compare : si $h_{\text{déchiffré}} = h(m')$, la signature est valide.
  • Pourquoi ça marche : $$\left(h(m)^{d}\right)^{e} = h(m)^{ed} \equiv h(m) \pmod n \qquad \text{car } ed \equiv 1 \pmod{\varphi(n)}$$ (c'est la même égalité qu'en 6.2, avec les rôles de $e$ et $d$ échangés, car $e$ et $d$ sont inverses l'un de l'autre.) 
from rsa_cles import *
from rsa_encrypt import *
import hashlib as hash

n, e, d = key_creation()   # Alice : (n,e) est publique, d est privée

# ---------- Côté Alice ----------
message = "Je déclare être bien l'auteur de ce texte par lequel je te déclare ma flamme. Bien romantiquement. Alice"
number_message_hash = int(hash.sha256(message.encode()).hexdigest(), 16)
signature = encryption(n, d, number_message_hash)      # h(m)^d  (avec la clé PRIVÉE)
# Alice envoie (message, signature) à Bernard

# ---------- Côté Bernard ----------
message_recu = message                                 # (ou une version modifiée en route)
hash_recu = int(hash.sha256(message_recu.encode()).hexdigest(), 16)
hash_decrypte = decryption(n, e, signature)            # (h(m)^d)^e  (avec la clé PUBLIQUE d'Alice)

print("Signature valide :", hash_decrypte == hash_recu)

Ce que prouve la vérification

  • Non-répudiation (authenticité) : seule Alice connaît $d$. Si le déchiffrement avec $e$ redonne bien une empreinte cohérente, c'est que la signature a été fabriquée avec $d$, donc par Alice. Elle ne peut pas nier en être l'auteur.
  • Intégrité : si le message est modifié en route, $h(m') \neq h(m)$ (une seule lettre changée donne une empreinte totalement différente) et la comparaison échoue.
Pourquoi pas $e$ pour signer ? Tout le monde connaît $e$ : n'importe qui pourrait produire une "signature" $h(m)^e$. Seul $d$, secret, rend la signature infalsifiable. C'est pour cela que encryption(n, d, ...) est appelée avec la clé privée.

Cas d'un message modifié

  • Si un attaquant change « Alice » en « Alicia » dans $m$, Bernard obtient $h(m')$ : 
    95055973276689786107989102804628048795374184475947868504737227745010401922767
  • Or $S^e \bmod n$ redonne toujours $4911551234\dots075052$. Les deux entiers sont différents : la vérification échoue, Bernard rejette le message.
  • L'attaquant ne peut pas non plus recalculer une signature pour son message modifié sans connaître $d$.

Démo : signer et vérifier

Mêmes clés que dans l'exemple ($n = 845\,479\,919$, $e = 423\,938\,503$, $d = 148\,621\,351$). Modifie le message reçu par Bernard et observe la vérification.

PGCD

Le plus grand diviseur commun de deux entiers. Deux entiers sont premiers entre eux quand leur pgcd vaut $1$. L'algorithme d'Euclide le calcule par divisions successives.

Relation de Bézout

Pour deux entiers $a$ et $b$ de pgcd $d$, il existe des entiers $u$ et $v$ tels que $au + bv = d$. Quand $d = 1$, $u$ est l'inverse de $a$ modulo $b$.

Exponentiation modulaire rapide

Méthode qui calcule $a^b \bmod n$ en parcourant les bits de $b$ : à chaque étape on élève au carré et on réduit modulo $n$. Le nombre d'opérations est de l'ordre de $\log_2 b$.

Inverse modulaire

Un entier $a$ est inversible modulo $m$ s'il existe $u$ tel que $a \cdot u \equiv 1 \pmod m$. C'est le cas exactement quand $\text{pgcd}(a, m) = 1$ ; $u$ se calcule avec l'algorithme d'Euclide étendu (coefficients de Bézout).

Clé publique

Le couple $(n, e)$, diffusé à tout le monde. Elle sert à chiffrer un message pour son propriétaire, ou à vérifier une signature qu'il a produite.

Clé privée

L'exposant $d$, connu uniquement de son propriétaire. Retrouver $d$ à partir de $(n, e)$ demande de factoriser $n$, ce qui est infaisable pour de grands nombres (ici $n$ est petit, c'est un exercice pédagogique).

Théorème d'Euler

Si $\text{pgcd}(a, n) = 1$, alors $a^{\varphi(n)} \equiv 1 \pmod n$. Pour $n = pq$ : $\varphi(n) = (p-1)(q-1)$. C'est ce qui garantit que le déchiffrement RSA retrouve le message.

Empreinte

Valeur de taille fixe $h(m)$ calculée à partir d'un message par une fonction de hachage. Deux messages différents ont (en pratique) deux empreintes différentes, et on ne peut pas retrouver le message à partir de son empreinte.

SHA-256

Fonction de hachage cryptographique produisant une empreinte de 256 bits (64 caractères hexadécimaux), quelle que soit la taille du message.

Non-répudiation

Garantie qu'un auteur ne peut pas nier avoir produit un message, parce que sa signature n'a pu être fabriquée qu'avec sa clé privée.

Intégrité

Garantie qu'un message reçu est identique à celui qui a été envoyé, sans modification en route.
